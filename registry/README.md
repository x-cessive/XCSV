# XCSV Component Registry

This directory holds the machine-readable inventory created by `XCSV-REFACTOR-INV-001` (#30).

## Authority

The registry is an index of evidence, not a replacement for source, runtime logs, receipts or Git history.

A component must not be called `LIVE` merely because it exists in the Exile catalogue or appears as LIVE in an older installation document.

Evidence is intentionally layered:

1. catalogue present
2. current source wired
3. packed artifact accounted for
4. deployed artifact present
5. current boot evidence
6. player runtime evidence

Unknown evidence remains `null`/`UNKNOWN`; it is not converted to false and it is never inferred true.

## Files

- `components.schema.json` — required schema/status vocabulary.
- `components.json` — authoritative registry once generated by the inventory lane. It should not be created as an empty placeholder and mistaken for a complete inventory.

## Refactor actions

Allowed working actions are:

- `KEEP_ACTIVE`
- `REFACTOR_ACTIVE`
- `CONSOLIDATE_DUPLICATE`
- `DISABLED_KEEP`
- `KEEP_VENDOR_REFERENCE`
- `ARCHIVE_CANDIDATE`
- `REMOVE_CANDIDATE`
- `UNKNOWN`

`REMOVE_CANDIDATE` never authorizes deletion by itself.

## Update contract

Any refactor that changes component ownership, wiring, artifact name, network registration, DB dependency, runtime status or canonical source must update the registry in the same work transaction.

Human-facing summaries belong in `wiki/System-Components.md`; generated Pages content under `docs/wiki` is not an independent authority.
